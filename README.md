# Vellume 0.9.0

## 0.9.0 렌더링·Dock·컴패니언·캐시 정리

- 정적 이미지는 화면 크기와 Fill/Fit/Stretch에 필요한 해상도로 WIC 축소 디코딩하며
  원본보다 확대 디코딩하지 않습니다. 화면이 커지거나 맞춤 방식이 바뀌면 원본에서
  다시 읽으므로 작은 캐시를 반복 확대하지 않습니다. 이미지 또는 디코딩 크기가
  바뀔 때 픽셀을 GPU에 업로드하고, 색상 변경은 기존 텍스처를 재사용합니다.
- 기본 색상으로 시작한 C++ 영상도 재생 중 밝기·대비·채도를 바꾸면 보정 가능한
  관리형 호환 렌더러로 전환합니다. 새 렌더러는 숨김·음소거 상태로 준비하며
  기존 일시정지·표시·볼륨 설정을 이어받습니다. 준비 실패 시 기존 재생을 유지합니다.
  현재 재생 위치/seek 인계 계약은 없어 최초 호환 전환 시 영상이 처음부터 재생될 수
  있습니다. 이후 색상을 기본값으로 돌려도 호환 프로세스를 유지하고, 월페이퍼를
  다시 적용할 때 C++ 경로를 재선택하여 슬라이더 조작 중 프로세스 교체를 줄입니다.
- Dock의 창·프로세스·휴지통 상태 수집과 실행 앱 아이콘 준비를 하나의 백그라운드
  작업으로 직렬화했습니다. UI 스레드는 결과만 반영하며 기존 이벤트 병합과 변경된
  항목만 갱신하는 동작을 유지합니다. 숨김·설정 변경·종료 시 오래된 결과는 버립니다.
- Codex 세션 파일 이벤트와 상태 읽기의 프로세스 조회를 1초 캐시로 합쳤습니다.
  상태 파일 교체가 공유/잠금/접근 오류로 실패하면 같은 메시지를 최대 4회 재시도합니다.
  실패한 최신 메시지는 상태 파일 옆의 단일 `.pending` 파일로 남기며, 후속 정상
  이벤트가 게시되면 소비합니다. 오래된 메시지를 자동 재생하지 않으며 ACK 프로토콜이나
  Codex 신뢰/권한 설정은 변경하지 않습니다. 영구 권한 오류는 로그 확인이 필요합니다.
- 영상 프록시는 30일 미사용 또는 전체 생성 캐시가 2 GiB를 초과하면 오래된 순서로
  정리합니다. 원본, 임시 변환 파일, 링크, 다른 파일은 대상이 아닙니다. 현재 렌더러의
  실제 소스와 적용 실패 후에도 참조할 수 있는 후보는 보호하며, 중지·연결 해제 시에도
  다음 성공 적용/앱 재시작까지 보수적으로 보호합니다. 보호 파일 때문에 상한을 넘을 수
  있습니다. 시작 복원 후 및 적용 시에만 정리하고, 새 변환이 없으면 10분 이내 반복
  스캔을 생략합니다. 지워진 프록시는 원본에서 다시 생성할 수 있습니다.

## 0.9.0 디스플레이 크기·혼합 배율 수정

- 모니터 위치와 해상도를 Windows 배율과 무관한 실제 픽셀 단위로 통일했습니다.
  WPF 앱과 C++ 렌더러는 Per-Monitor V2 DPI 인식을 사용하며, 100%·125% 등
  서로 다른 배율의 모니터에서도 바탕화면 창을 실제 화면 크기에 맞춰 배치합니다.
- 모니터 연결·해제, 해상도·배치 및 주 모니터 변경을 Windows 이벤트로 받아
  디스플레이 목록과 각 월페이퍼의 출력 영역을 갱신합니다. 위젯과 Dock은
  현재 주 모니터를 따라가고, 월페이퍼 지정은 기존 디스플레이 ID별로 유지됩니다.
- 크기나 위치만 바뀌면 살아 있는 렌더러 창과 영상 재생 세션을 유지합니다.
  모니터가 분리되어 창을 닫아야 하는 경우에는 지정한 월페이퍼와 일시정지 상태를
  보관했다가 같은 디스플레이가 다시 연결될 때 복원합니다.
- 이 수정의 DPI 설정은 프로세스 시작 시 적용되므로 기존 실행 중인 앱을
  종료한 후 새 빌드로 다시 실행해야 합니다.

## 0.9.0 DWM 영상 합성 안정화

- 네이티브 영상은 Media Foundation의 HWND 재생을 유지하되 렌더러 창의
  `WS_EX_NOREDIRECTIONBITMAP`을 제거했습니다. 전체 화면 크기의 WorkerW 자식 창도
  DWM 리디렉션 표면에서 합성되므로 Unreal Editor와 함께 표시될 때 MPO·독립 Flip·
  일반 합성 경로 사이를 오갈 가능성을 줄입니다.
- 영상 프레임을 CPU로 복사하거나 Vellume D3D11 swap chain에서 다시 그리지 않으므로
  기존 1080p 30fps 프록시의 낮은 디코딩 비용과 연속 재생 방식은 유지됩니다.
- 드라이버별 비교가 필요하면 실행 전에
  `VELLUME_NATIVE_LEGACY_NOREDIRECTION=1`을 설정해 이전 창 경로로 즉시 되돌릴 수
  있습니다. Windows 전역 MPO 레지스트리나 Unreal 설정은 변경하지 않습니다.

## 0.9.0 포그라운드 앱에서도 연속 재생

- Unreal Editor를 포함한 다른 앱이 최대화·전체 화면·포그라운드 상태가 되어도
  월페이퍼 영상과 위젯을 자동으로 일시정지하지 않습니다. 창 전환 때 발생하던
  정지·재개 및 렌더러 상태 전환도 없어집니다.
- 영상은 기존의 디스플레이 해상도별 최대 30fps H.264 최적화 프록시를 계속
  사용합니다. 포그라운드 앱이 GPU를 우선 사용할 때는 Windows의 GPU 스케줄링에
  따라 Vellume의 실제 점유율이 자연스럽게 낮아지며, 재생 화면은 유지됩니다.
- 이전 버전의 최대화 창 감지 값과 앱별 자동 재생 규칙은 런타임에서 무시합니다.
  사용자가 누르는 전체·디스플레이별 일시정지와 중지 기능은 그대로 유지됩니다.

## 0.9.0 영상 GPU 사용량 자동 최적화

- 관리형 라이브러리의 고해상도·고프레임·AV1/VP9 영상은 원본을 보존한 채
  디스플레이 해상도에 맞는 최대 30fps H.264 프록시를 항목 내부의
  `.vellume-cache`에 한 번만 생성합니다. 이후 적용과 재시작에서는 캐시를
  즉시 재사용합니다.
- 1080p 화면에서 4K 영상을 매 프레임 디코딩하고 축소하던 비용을 줄입니다.
  H.264/HEVC 영상이 이미 화면 해상도 이하이고 30fps 이하라면 원본을 그대로
  사용해 불필요한 재인코딩을 하지 않습니다.
- 변환은 UI 스레드 밖의 FFmpeg 자식 프로세스에서 실행하며 NVIDIA NVENC를
  먼저 사용하고 실패하면 소프트웨어 H.264로 폴백합니다. 임시 파일을 완성한
  뒤에만 캐시로 교체하므로 취소·비정상 종료 시 손상된 파일이 재생되지 않습니다.
- 설정의 `영상 GPU 사용량 자동 최적화`에서 디스플레이별로 켜고 끌 수 있습니다.
  FFmpeg/FFprobe가 앱 폴더나 `PATH`에 없거나 변환이 실패하면 월페이퍼 적용을
  막지 않고 원본 영상으로 즉시 폴백합니다. `VELLUME_FFMPEG_PATH`와
  `VELLUME_FFPROBE_PATH`로 실행 파일 위치를 직접 지정할 수도 있습니다.

## 0.9.0 Windows 작업표시줄 표시 전환

- 설정 > 위젯의 Vellume Dock 카드에서 `Windows 작업표시줄 표시`를 즉시
  켜고 끌 수 있으며 선택은 JSON에 저장되어 다음 실행에도 유지됩니다.
- 표시를 켜면 기본·보조 모니터의 작업표시줄을 즉시 복원하고 30초 숨김 유지
  타이머를 중단합니다. 표시를 끄면 Vellume 실행 중 작업표시줄을 숨깁니다.
- Explorer의 `TaskbarCreated` 알림뿐 아니라 `EVENT_OBJECT_SHOW`를
  이벤트 기반으로 감시하는 동작은 작업표시줄 표시가 꺼졌을 때만 활성화됩니다.
  Vellume 정상 종료와 비정상 종료 복구 가드는 설정과 관계없이 작업표시줄을
  정상 상태로 복원합니다.

## 0.9.0 C++ 네이티브 월페이퍼 렌더러

- 설정·Dock·위젯·수명 주기는 기존 .NET 8/WPF 앱에 유지하고, 화면 전체를
  차지하는 이미지·영상 렌더링만 별도 C++20 x64 프로세스로 분리했습니다.
- 정적 이미지는 WIC로 디코딩한 뒤 D3D11 composition swap chain과
  Direct2D/DirectComposition으로 제출합니다. 렌더 HWND에는
  `WS_EX_LAYERED`를 사용하지 않습니다.
- MP4/WebM 영상은 C++ Media Foundation Media Engine이 같은 비계층 HWND에
  직접 반복 재생합니다. 콜백으로 실제 첫 프레임을 확인한 뒤만 창을
  표시하며, 일시정지·재개·음소거·볼륨·Fill/Fit/Stretch를 지원합니다.
- C# 제어부와 렌더러는 버전이 붙은 길이 제한 바이너리 IPC를 사용합니다.
  명령 스트림 EOF와 명시적 Close 모두 동일한 D3D/COM/HWND 정리 경로를
  사용하며 Explorer 또는 렌더러를 강제 종료하지 않습니다.
- 이미지·영상 네이티브 초기화나 시스템 코덱이 실패하면 기존 관리형
  RenderHost로 자동 폴백합니다. GIF와 로컬 HTML은 현재의 검증된 WIC 및
  WebView2 호환 경로를 유지합니다.
- Explorer가 WorkerW/Progman을 다시 만들면 마지막 소스와 재생 상태를
  보존한 채 C++ 창을 새 데스크톱 호스트에 재연결합니다.
- `VELLUME_DISABLE_NATIVE_RENDERER=1`을 설정하면 재빌드 없이 관리형
  렌더러만 사용하는 A/B 비교가 가능합니다.

## 0.9.0 렌더링 기준선·런타임 정리

- 효과가 없었던 0.8.36 DWM Cloak 실험을 완전히 롤백했습니다. 최대화 앱에서는 0.8.35와 동일하게 렌더 프로세스와 HWND를 유지한 채 재생만 일시정지합니다.
- 더 이상 호출되지 않던 과거 Unreal 전용 정적 프레임, warm-parking HWND, 렌더 호스트 격리 종료·복원 IPC와 전용 영상 프레임 추출기를 제거했습니다. 설정에 남은 `StopFreeMemory` 값은 호환성을 위해 일반 일시정지로 계속 해석합니다.
- RenderHost의 상태 메시지에서 사용하지 않는 격리 상태와 재생 위치 필드를 제거하여 현재 동작에 필요한 연결·표시·재생 명령만 유지합니다.
- Dock 포그라운드 갱신은 항목마다 `GetForegroundWindow`를 반복 호출하지 않고 한 번 읽은 결과를 전체 아이콘에 일괄 반영합니다. 실행 창 전체 조사는 기존처럼 Shell/WinEvent 변경 시 병합 실행되고 30초 검사는 안전망으로만 남습니다.
- 구버전에서 비정상 종료되어 Windows 배경 복원이 보류된 경우를 위한 `GpuSafety` 복구 판독은 유지했습니다. 신규 실행에서는 제거된 격리 경로를 생성하지 않습니다.

## 0.8.35 관리형 라이브러리·추가 최적화

- 이미지·GIF·MP4/WebM·HTML 파일을 등록하면 `%LocalAppData%\Vellume\Library\<항목 ID>`로 복사하고 이후에는 관리 복사본을 재생합니다. `index.html` 폴더를 등록하면 하위 리소스까지 함께 복사합니다.
- 0.8.34 이하에서 외부 경로로 등록한 기존 항목은 앱 시작 시 관리형 저장소로 자동 이전합니다. 활성 월페이퍼와 모니터별 프로필도 같은 관리 파일을 가리키도록 함께 갱신하며 원본 파일은 삭제하지 않습니다.
- 라이브러리에서 항목을 제거하면 Vellume이 소유한 해당 항목 폴더만 삭제합니다. 임의의 외부 원본 경로는 절대 삭제하지 않으며, 중단된 가져오기와 설정에 없는 고아 항목 폴더는 다음 시작 때 정리합니다.
- 대용량 파일 복사·폴더 삭제·JSON 직렬화의 내부 연속 작업이 WPF UI 컨텍스트를 점유하지 않도록 비동기 경로를 정리했습니다. 여러 위치에 중복되어 있던 월페이퍼 모델 복사 코드도 단일 `Copy()` 구현으로 통합했습니다.

## 0.8.34 음악 기능·미사용 경로 제거

- 데스크톱 Now Playing 패널, Windows 미디어 세션 감시, 이전·재생·다음 조작 창, 앨범 아트, 오디오 스펙트럼 캡처·렌더링 코드를 완전히 제거했습니다.
- `NAudio.Wasapi`와 `NAudio.Core` 의존성을 제거했습니다. 영상 월페이퍼의 Media Foundation 재생과 음소거·볼륨은 별도 경로이므로 그대로 지원합니다.
- 이미 사용하지 않던 달력 설정 필드와 전체 화면 위젯 합성 Z-order 분기를 제거했습니다. 위젯은 현재 사용 중인 좌·우 bounded alpha surface 경로만 유지합니다.
- 사용자가 라이브러리에 추가한 이미지·GIF·영상·HTML은 원본 위치에서 직접 읽습니다. Vellume은 원본 미디어를 LocalAppData나 설치 폴더로 복사하지 않고 절대 경로만 `settings.json`에 저장합니다.
- `%LocalAppData%\Vellume\GpuSafety`에는 비정상 종료 복구용으로 생성한 임시 BMP 프레임과 표식만 저장될 수 있으며, 정상 인계·복구 시 삭제합니다. 이는 원본 파일의 복사본이 아닙니다.

## 0.8.33 최대화 창 자동 절전

- 전경 창이 최대화 상태이며 현재 모니터 작업 영역의 97% 이상을 덮으면 월페이퍼 디코더와 위젯 갱신을 일시정지합니다. 프로세스명에 의존하지 않으므로 Unreal Editor뿐 아니라 같은 조건의 다른 앱에도 동일하게 적용됩니다.
- Restore Down, 최소화 또는 다른 창 전환 시 기존 렌더러를 종료·재생성하지 않고 같은 인스턴스에서 즉시 재생을 이어갑니다. Dock은 자동 절전 대상에서 제외되어 계속 사용할 수 있습니다.
- 탐색기, 바탕화면, Windows 셸과 Vellume 자체 창은 제외합니다. 진짜 전체 화면 Direct3D 및 테두리 없는 전체 화면 앱도 기존처럼 일시정지합니다.
- 최대화와 복원은 전역 위치 이벤트를 계속 구독하지 않고 현재 전경 창의 UI 스레드에만 제한한 WinEvent로 감지합니다. 이벤트 유실에 대비한 10초 저빈도 감시만 보조 수단으로 유지합니다.

## 0.8.32 렌더링·갱신 최적화

- 컴파일러·분석기 경고를 실제 코드 수정으로 제거했습니다. 로컬 우선 빌드가 NuGet 감사 서버 상태에 종속되지 않도록 자동 감사는 끄고 패키지 버전은 계속 고정합니다.
- 좌·우 위젯 HWND는 각각 하나로 유지하면서 시계, 시스템, 미디어, Codex 중 변경된 패널 영역만 2배 슈퍼샘플링해 기존 DIB에 덮어씁니다. Unreal 호환 레이어 수를 늘리지 않고 전체 면 재래스터화를 줄였습니다.
- 시스템 계측과 미디어·Codex 갱신 전용 잠금을 월페이퍼 적용·중지 잠금에서 분리해 느린 GPU·디스크·계정 조회가 조작과 Explorer 재연결을 막지 않게 했습니다.
- Dock은 포커스 변경 시 기존 창 스냅샷의 활성 상태만 바꾸며, 창 생성·종료·알림 때만 전체 `EnumWindows` 조사를 수행합니다. 휴지통 아이콘도 별도 부분 갱신합니다.
- GIF는 Chromium 대신 WIC 프레임과 단일 WPF 자식 표면으로 재생하고 30FPS 상한을 적용합니다. WebM은 Media Foundation을 먼저 사용하고 시스템 코덱이 지원하지 않을 때만 WebView2로 폴백합니다.

## 0.8.31 Unreal 전용 처리 제거

- UnrealEditor, UE4Editor, UE5Editor에 자동으로 적용하던 `실행 중 · 완전 정지` 규칙을 제거했습니다. 이제 Unreal Editor도 Unity, Visual Studio, Blender 같은 다른 집중 작업 앱과 동일한 일반 일시정지 경로를 사용합니다.
- Unreal 전용 프로세스 조사기, 안정화 타이머, Windows 배경 인계 분기와 종료 후 재실행 가드를 코드에서 제거했습니다. Vellume 렌더러 프로세스나 창을 Unreal 때문에 종료·재생성하지 않습니다.
- 설정 스키마를 17로 올리고 기존 전역 설정과 디스플레이별 설정에 저장된 Unreal 전용 규칙을 한 번 제거합니다. 다른 사용자가 직접 만든 앱 규칙은 유지합니다.
- 전체 화면 게임과 앱은 기존처럼 Windows Direct3D 전체 화면 신호, 실제 테두리 없는 전체 화면, 일반 고부하 앱 기준으로 정지하며 모든 모니터에 동일하게 반영됩니다.
- Unreal Editor의 Slate/Content Drawer 깜빡임은 Vellume 전체 프로세스를 종료하지 않는 한 완전히 사라지지 않는 환경 특성으로 보고, 더 이상 불완전한 전용 우회 동작을 추가하지 않습니다.

## 0.8.30 1.0 전 최적화 패스

- 시스템 위젯의 CPU와 메모리는 1초 반응성을 유지하되 GPU는 2초, C/D 디스크는 30초 주기로 분리했습니다. 디스크 목록은 한 번만 조회하고 GPU PDH 버퍼를 재사용합니다.
- 투명 위젯 표면은 최초 프레임 이후 일반 실행에서 전체 알파 픽셀을 반복 검사하지 않습니다. 2배 슈퍼샘플링 화질과 Unreal 호환 단일 좌/우 표면 구조는 유지합니다.
- Dock 창 변경 이벤트를 160ms 동안 병합하고 PID별 실행 파일·앱 이름 및 아이콘을 캐시해 짧은 시간의 중복 전체 창 조사를 줄였습니다.
- 설정 창이 숨겨지면 설정 UI 전용 30초 프로세스 조사와 Shell 알림 구독을 중지하고, 다시 열 때 즉시 갱신합니다. 상시 표시되는 Dock의 감지와 단축키는 그대로 작동합니다.
- 선택적인 로컬 성능 진단을 추가했습니다. 실행 전에 `VELLUME_PERFORMANCE_LOG=1`을 설정하면 외부 전송 없이 기존 LocalAppData 오류 로그에 위젯 렌더 시간, Dock/설정 창 조사 시간, 메모리, GDI/USER 객체를 1분 단위로 기록합니다.
- 느린 GPU·디스크 계측이 연속 호출에서 재사용되는지 확인하는 회귀 테스트를 추가했습니다.

## 0.8.28 Dock 구역과 전체 화면 정지 동기화

- Dock 고정 항목을 `기본 앱`, `개발`, `도구`, `게임` 네 구역으로 분류하고
  이름표 없이 얇은 세로 경계선만 표시합니다. 잘못 저장된 예전 그룹보다
  알려진 실행 파일 종류를 우선해 Whale·Firefox·Discord 같은 도구와
  Visual Studio 계열, 게임 런처를 안정적으로 나눕니다.
- Discord가 트레이에 숨겨진 상태에서 내부 Electron 창을 억지로 복원하지
  않습니다. 표시 가능한 창이 없으면 Discord 공식 바로가기와 동일한
  Squirrel `Update.exe --processStart Discord.exe` 경로로 활성화를 요청합니다.
- 일반 최대화 창만으로 월페이퍼를 정지하지 않습니다. Windows 공개
  `SHQueryUserNotificationState`의 독점 Direct3D 전체 화면 신호, 테두리 없는
  실제 모니터 전체 화면, 명시적인 집중 작업 규칙을 자동 정지 기준으로
  사용합니다.
- 기본 모니터에서 판정한 자동 정지·해제 상태를 모든 보조 모니터 렌더러에
  전달합니다. 개별 모니터의 수동 일시정지 상태는 자동 해제 후에도
  유지됩니다.

## 0.8.26 모니터별 월페이퍼

- 기본·보조 모니터가 각자 독립된 월페이퍼 렌더 프로세스를 유지합니다.
  디스플레이 화면에서 대상 모니터를 선택한 뒤 라이브러리의 `적용`을 누르면
  기존 화면을 교체하지 않고 선택한 화면에만 적용됩니다.
- Fill/Fit/Stretch, 음소거와 볼륨은 모니터별 프로필로 JSON에 저장됩니다.
  앱 시작 복원이 켜져 있으면 현재 연결된 각 모니터의 마지막 월페이퍼를
  순서대로 복원합니다. 0.8.25 이하의 단일 활성 월페이퍼 설정은 기존 선택
  모니터의 첫 프로필로 자동 이전됩니다.
- 시계·시스템·Codex 컴패니언과 Dock은 중복 생성하지 않고 기본 모니터에
  마스터 한 세트만 유지합니다.
- `선택 화면 중지`와 `모두 중지`를 구분했습니다. Explorer가 WorkerW를
  다시 만들면 보조 모니터 렌더러도 각각 재연결합니다.
- Dock 다중 창 메뉴는 Windows 기본 `MenuItem`의 단축키·서브메뉴 예약 열을
  쓰지 않는 전용 420px 행 템플릿으로 교체했습니다. 닫기 버튼이 행의 실제
  오른쪽 끝에 정렬됩니다.

## 0.8.25 Dock 드래그 오작동 방지

- Dock 아이콘은 마우스를 누른 뒤 350ms가 지나고 시스템 드래그 거리까지
  이동했을 때만 드래그 앤 드롭을 시작합니다.
- 짧은 좌클릭으로 창 선택 목록을 닫거나 다른 아이콘을 누를 때는 드래그
  후보를 MouseUp 즉시 초기화해 기본 폴더 아이콘 등이 이동 대상으로
  튀어나오는 오작동을 막았습니다.

## 0.8.24 Dock 닫기와 탐색기 중복 제거

- 창 선택 메뉴의 닫기 컨트롤을 오른쪽 끝 고정 폭으로 배치하고 시스템

  Explorer 창 생성·종료 사이에 노란 기본 폴더 아이콘이 순간적으로
  중복 삽입되던 현상을 막습니다.

## 0.8.17 Codex Hook 신뢰 안정화

## 0.8.6 다중 레이어 정리

- 시계·시스템·미디어·Codex 위젯은 각각 창을 만들지 않습니다. 같은 쪽에
  놓인 위젯을 한 번에 합성하여 좌측 최대 1개, 우측 최대 1개의 bounded
  alpha surface만 유지합니다.
- Unreal 호환 규칙이 켜져도 RenderHost와 월페이퍼 창을 종료·재생성하지
  않습니다. 현재 화면을 유지한 채 영상 디코더와 위젯 갱신만 일시정지하고,
  Unreal 창이 최소화되거나 닫히면 같은 창에서 바로 재생합니다.
- `StopFreeMemory` 규칙은 대상 프로세스가 존재하는지만 보지 않고, 보이는
  비최소화 최상위 창이 있을 때만 적용됩니다.
- 첨부 진단에는 영상의 `nestedVideoWindow=false`, 위젯의 `panelCount`가
  기록되어 실제 합성면 수를 확인할 수 있습니다.

호환성을 우선한 현재 네이티브 단일 창 경로에서는 영상 색상 보정을 위한
추가 전체 화면 레이어를 만들지 않습니다.

## 0.8.5 네이티브 MP4 재생 경로

일반 MP4 월페이퍼는 Chromium/WebView2가 아니라 Windows Media Foundation으로
재생합니다. Fill, Fit, Stretch와 100% 이하의 밝기 조절은 네이티브 영상 창에서
처리하므로, 현재 사용 중인 밝기 59.6% 설정도 WebView2로 되돌아가지 않습니다.
설정 변경으로 네이티브 조건을 만족하게 되면 실행 중인 WebView2 월페이퍼도
Media Foundation으로 다시 전환합니다.

WebView2는 로컬 HTML, GIF, WebM 및 Media Foundation 경로에서 아직 처리하지 않는
대비·채도·100% 초과 밝기 보정의 호환 재생기에만 남아 있습니다. 앱의 월페이퍼
상태에는 실제 선택된 재생기가 `Media Foundation` 또는 `WebView2`로 표시됩니다.

Unreal Editor가 최소화된 동안 화면 밖 `-32000,-32000` 위치에 생성되는 Content
Drawer/Slate 보조 창은 활성 편집기 창으로 취급하지 않습니다. 이 보조 창 때문에
GPU 격리가 빠르게 해제·재진입하며 월페이퍼가 재로드되던 경로를 차단했습니다.

## Unreal Content Drawer 호환 Dock

Dock은 더 이상 WPF의 `AllowsTransparency=True`를 사용하지 않습니다. 떠 있는
Unreal Content Drawer가 별도 Slate 합성 표면을 만들 때 per-pixel layered
Dock과 DWM 갱신이 충돌하던 경로를 제거했습니다. Dock은 일반 top-level HWND와
DWM glass frame을 사용하므로 반투명 외형과 둥근 모서리를 유지하면서
`WS_EX_LAYERED` 합성 레이어를 만들지 않습니다.

## Unreal Editor 무합성 대기 모드

Unreal Editor 격리 모드에서 RenderHost 프로세스와 IPC 연결은 대기 상태로
유지하지만, Media Foundation의 GPU 출력 표면과 전체 화면 렌더러 HWND는
완전히 해제합니다. 재생 위치의 안전 프레임은 Windows 배경으로 유지합니다.
Unreal Editor를 최소화하면 기존 RenderHost 프로세스 안에서 렌더러만 다시
준비하므로 새 프로세스를 시작하는 지연은 발생하지 않습니다.

시계·시스템 정보·퀵슬롯 같은 보조 위젯도 격리 중에는 창을 폐기하지 않고
일시정지와 숨김만 적용합니다. 복귀할 때 기존 HWND를 다시 표시하므로 위젯
재생성에 따른 회색 플래시와 리로드를 줄입니다. 영상 디코더 자체는 Unreal과
GPU 합성 충돌을 만들지 않도록 격리 중 해제되며, 안전 프레임 뒤에서 첫 영상
프레임이 준비된 뒤 공개됩니다.

Vellume은 Windows 10/11 바탕화면에서 로컬 월페이퍼, 시스템 정보,
퀵슬롯과 로컬 애드온을 실행하는 개인용 WPF 데스크톱 앱입니다.
계정, 결제, 분석 수집, 외부 서버 기능은 없으며 Wallpaper Engine의
코드나 리소스를 사용하지 않은 독립 구현입니다.

## 0.8.5 지속 안전 프레임·Dock 창 선택

Unreal Editor를 최소화할 때마다 Windows 시스템 배경을 원래 이미지로
되돌렸다가 Vellume 영상을 다시 올리던 흐름을 제거했습니다. 첫 격리에서
만든 Vellume 안전 프레임을 현재 세션의 영상 렌더러 아래에 계속 유지하므로
복귀 중 `회색 화면 → 예전 Windows 배경 → Vellume` 순서로 바뀌지 않습니다.
원래 Windows 배경은 월페이퍼 중지 또는 Vellume 정상 종료 때 복원됩니다.
Dock과 위젯도 영상 디코더의 첫 프레임을 기다리지 않고 먼저 복원됩니다.
Dock은 작은 소프트웨어 렌더링 독립 창이므로 GPU 격리 중에도 종료하거나
숨기지 않으며, 숨겨 둔 Windows 작업표시줄도 그대로 유지합니다.

Dock의 고정 앱도 실행 중 창 정보를 공유합니다. 탐색기·Whale·Firefox·
KakaoTalk처럼 창이 둘 이상이면 좌클릭으로 순환하고, 우클릭
`열린 창 (N)` 하위 목록에서 원하는 창을 바로 선택할 수 있습니다.

설정의 `Windows 로그인 시 Vellume 자동 실행`을 켜면 관리자 권한 없이
현재 사용자 계정의 로그인 자동 실행에 등록됩니다. 로그인으로 시작할 때는
설정 창을 띄우지 않고 마지막 월페이퍼, 위젯과 Dock을 복원합니다.

## 0.8.5 빠른 최소화 복귀 패치

Unreal Editor를 최소화해 데스크톱으로 돌아올 때 잠시 다른 장면이나 다른
화면 비율의 영상 썸네일이 보이던 문제를 수정했습니다. MP4는 격리 직전의
실제 재생 위치에서 한 프레임을 Media Foundation으로 디코딩하고, 현재
Fill/Fit/Stretch와 밝기·대비·채도 설정을 그대로 적용해 Windows 안전
배경으로 넘깁니다. 프레임 추출에 실패한 경우에만 기존 Shell 썸네일을
사용합니다.

전경 창 이벤트의 디바운스는 120ms에서 40ms, Unreal 최소화 후 격리 해제
안정화 시간은 450ms에서 120ms로 줄였습니다. 따라서 새 RenderHost의 첫
프레임 보호는 유지하면서 불필요한 약 0.4초 대기를 제거했습니다.

## 0.8.5 Seamless First-Frame Handoff

0.8.5는 고부하 앱을 최소화한 뒤 월페이퍼를 복원할 때 전체 화면이
Windows 기본 회색(`#696969`)으로 약 0.4초 번쩍이던 문제를 수정합니다.
새 RenderHost와 Media Foundation 영상 표면을 숨긴 상태로 초기화하고,
첫 디코드 프레임이 준비된 다음에만 화면에 표시합니다. Windows가 보관한
안전 배경도 새 프레임이 실제로 표시된 뒤 해제하므로 빈 전체 화면
`Static` 창이 시계·시스템 정보·Codex 위젯을 덮지 않습니다.

사용 빈도가 낮고 별도 미디어 세션 감시가 필요했던 좌상단 Now Playing
플레이어, 스펙트럼과 설정 버튼은 UI 및 런타임에서 비활성화했습니다.
MP4/WebM 월페이퍼 재생에 사용하는 Media Foundation 디코더는 별개이므로
영상 월페이퍼 기능에는 영향이 없습니다.

이번 롤백 빌드는 이후 버전에서 저장된 로컬 설정도 계속 읽습니다. 특히
0.8.7 계열에서 자동 변경된 기본 Unreal `일시정지` 규칙 세 개는
0.8.5의 `완전 정지` 규칙으로 되돌려, 기존 사용자 설정 때문에 롤백
동작이 무효화되지 않도록 했습니다. 사용자가 별도로 만든 규칙은 유지합니다.

## 0.8.4 Literal Transparent Bridge

0.8.3의 bounded 위젯 브리지는 Windows `Static + SS_BLACKRECT`가 실제로
칠한 `#696969`와 다른 `#646464`를 투명 컬러 키로 사용했습니다. 그 결과
시계, 시스템 정보, Codex 컴패니언의 투명 영역에 회색 직사각형이 남았습니다.

0.8.4는 테마 의존적인 `Static` 배경을 제거하고 Vellume 전용 Win32 클래스를
등록합니다. 전용 클래스가 고정색 `#010203`을 직접 칠하고, 정확히 같은 값을
layered 컬러 키로 사용합니다. 최초 표시와 데스크톱 재부착 전에 숨겨진
브리지 표면을 동기적으로 채워 복귀 프레임의 배경 노출도 차단합니다.
회귀 테스트는 속성값만 확인하지 않고 `WM_PRINTCLIENT`로 실제 픽셀을 렌더링해
브리지 배경이 고정 컬러 키와 일치하는지 검증합니다.

## 0.8.3 Alpha-Safe Widget Resume

0.8.3은 Unreal Editor 최소화 후 위젯을 데스크톱 호스트에 다시 연결할 때
시계·시스템 패널의 사각형 경계 전체가 Windows 기본 회색으로 한 프레임
노출되던 문제를 수정합니다.

- 위젯 브리지와 layered alpha 자식 창을 처음부터 숨긴 상태로 생성
- 위치 변경과 재부착에서 `SWP_SHOWWINDOW`를 제거
- `SetParent` 뒤 캐시된 premultiplied BGRA 프레임을 숨은 상태에서 재전송
- 준비된 alpha 자식을 먼저 표시한 뒤 투명 브리지를 마지막에 표시
- 유효한 알파 프레임이 없으면 위젯 HWND를 공개하지 않음

따라서 최소화 복귀 시 Windows `Static` 창의 기본 배경색이 바탕화면에
합성되지 않으며, 기존 위젯 디자인의 투명 영역만 그대로 보입니다.

## 0.8.2 Minimize Resume

0.8.2는 Unreal Editor가 실행된 채 최소화됐을 때 `완전 정지`가 풀리지 않아
월페이퍼·위젯·Dock이 계속 사라져 있던 문제를 수정합니다. Windows 최소화
이벤트를 받은 뒤 모든 표시 가능한 Unreal 최상위 창이 최소화됐는지 확인하고,
450ms 안정화 구간 후 RenderHost와 Dock을 복원하며 위젯 갱신을 재개합니다.
Unreal 창을 다시 복원하면 기존의 강한 GPU 격리를 다시 적용하므로 0.8.1에서
해결한 Unreal 화면 깜빡임 방지는 유지됩니다.

평가 도중 추가 최소화·복원 이벤트가 들어와도 마지막 상태를 한 번 더
평가하도록 대기 플래그를 두어, 10초 watchdog까지 복원이 늦어지는 경우도
막았습니다. 이 경로는 폴링을 추가하지 않고 기존 `SetWinEventHook` 이벤트를
사용합니다.

## 0.8.1 Bounded Widget Hosts

0.8.1은 Windows 11의 raised Progman에서 직접 layered child 픽셀이
누락되는 문제를 수정합니다. 시계, 시스템, 미디어, Codex 위젯은 각각
작은 리디렉션 호스트와 premultiplied-alpha 표면을 사용하며, 모니터 전체
크기의 위젯 표면은 만들지 않습니다. 동일한 위젯 설정을 다시 저장해도
HWND를 파괴하거나 다시 만들지 않습니다.

0.8.1에서는 Rainmeter의 스킨 창 구조를 참고해 기존의 모니터 전체 크기
위젯 surface를 제거하고, 시계·시스템 정보·미디어 플레이어·Codex 컴패니언을
각각 콘텐츠 영역으로 경계가 제한된(bounded) layered HWND로 분리합니다.
월페이퍼 렌더러가 WorkerW에 연결되는 기존 구조는 유지하며, 각 위젯 HWND는
전체 화면 브리지 없이 WorkerW 또는 Progman에 직접 연결해 관리합니다.

- 네 위젯은 별도 프로세스 네 개가 아니라 동일한 Vellume 프로세스 안의
  독립 HWND 네 개로 실행됩니다.
- 각 위젯은 per-pixel alpha를 사용하는 작은 투명 surface만 합성합니다.
- 투명 영역은 click-through로 처리해 바탕화면과 다른 창의 입력을 막지
  않으며, 위젯의 실제 상호작용 영역만 입력을 받습니다.
- 각 layered HWND는 갱신 때마다 버퍼를 다시 생성하지 않고 기존 GDI
  surface를 재사용합니다.
- 앱별 `완전 정지` 규칙에서는 GPU 월페이퍼와 상호작용 오버레이만 해제하고,
  bounded 정보 위젯은 숨김·정지 상태로 유지해 복귀 때 재로딩하지 않습니다.
- 전체 화면 투명 위젯 surface와 그 검은 배경을 제거해 DWM의 합성 범위,
  불필요한 화면 갱신과 GPU 간섭을 줄이는 것이 목적입니다.

이 구조는 위젯 하나가 바뀔 때 해당 위젯의 작은 영역만 다시 합성할 수 있어
전체 화면 오버레이보다 Unreal Editor와의 충돌 가능성을 낮춥니다. 다만
독립 HWND와 GDI surface 재사용만으로 특정 GPU·드라이버·DWM 조합의 문제를
완전히 해결한다고 보장할 수는 없습니다. 기존 방식과 0.8.1 방식을 같은
환경에서 비교하는 실제 Unreal A/B 검증이 필요합니다.

설계 근거:

- [Rainmeter Skin 창 생성과 갱신 구조](https://github.com/rainmeter/rainmeter/blob/master/Library/Skin.cpp)
- [Rainmeter 스킨 개념](https://docs.rainmeter.net/manual/skins/)
- [Microsoft UpdateLayeredWindow](https://learn.microsoft.com/windows/win32/api/winuser/nf-winuser-updatelayeredwindow)

### 안정성과 자원 사용

- 전경 전환·최소화/복원·창 생성/종료는 `SetWinEventHook`, Dock과
  퀵슬롯 실행 상태·attention은 Windows Shell Hook으로 즉시 갱신
- 휴지통은 500ms 반복 조회 대신 Recycle Bin Shell namespace 변경
  알림이 도착할 때만 `SHQueryRecycleBin`으로 비어 있는지 확인
- Explorer의 `TaskbarCreated` 또는 작업표시줄 `EVENT_OBJECT_SHOW` 이벤트가
  오면 WorkerW를 재연결합니다. 작업표시줄 숨김이 선택된 경우에만 다시 숨기며,
  이벤트 누락 복구용 전체 점검은 30초 간격으로만 수행
- Codex는 `status.json` 파일 변경 이벤트로 갱신해 기존 상태 폴링을 제거
- 시간·CPU·GPU·메모리·디스크처럼 구간 표본이 필요한 값만 1초
  샘플링을 유지하고 전경 앱 점검은 이벤트 누락 대비 10초 watchdog만 유지
- 기본 보정 MP4/WebM과 정적 이미지 월페이퍼에서는 전체 화면 WebView2 합성 표면을
  생성하지 않아 Chromium GPU 프로세스의 가장 큰 부하를 제거

- 장시간 살아 있는 WPF 제어부는 소프트웨어 렌더링으로 고정해 Unreal과

- 완전 정지 대상 프로세스가 끝나거나 모든 표시 창이 최소화되면 저장한

## 애드온

### 데스크톱 미디어 플레이어

Now Playing 패널, 오디오 스펙트럼과 데스크톱 미디어 조작 버튼은 현재
제거되어 설정 화면에 표시되지 않으며 런타임 창도 생성하지 않습니다.
이 변경은 MP4·WebM 월페이퍼 재생과 월페이퍼의 재생·일시정지 기능에는
영향을 주지 않습니다.

### Codex 컴패니언

청록색 트윈테일과 분홍·검정 지뢰계 의상의 Vellume 전용 원본 컴패니언이
월페이퍼와 독립적으로 좌측 상단에 표시됩니다. Codex Desktop 실행 여부와
로컬 세션 활동은 자동으로 연결되므로 Hook을 설치하지 않아도
연결·작업 중·대기 상태가 표시됩니다.

컴패니언 캐릭터는 현재 상태에 맞춰 자세가 바뀝니다. 연결 대기에는 기본
자세, 요청 분석에는 생각하는 자세, 빌드·편집·도구 사용에는 작업 자세,
`Stop`에는 완료 자세, Codex 종료에는 수면 자세를 사용합니다. 상태 이미지는
프로세스 시작 시 한 번만 디코딩해 캐시하며 상태가 실제로 바뀔 때만 교체합니다.

선택 사항인 **상세 상태 연결** 버튼은 기존 `~/.codex/hooks.json`을
보존하고 다음 공식 수명 주기 훅에 Vellume 명령만 병합합니다.

- `SessionStart`: 연결됨
- `UserPromptSubmit`: 생각 중
- `PreToolUse`: 빌드·편집·도구 사용 중
- `Stop`: 작업 완료

Codex 종료·오프라인 전환은 별도 Hook 없이 로컬 프로세스 종료 이벤트로
감지합니다.

상세 연결 설치 후 Codex를 다시 시작하고 `/hooks`에서 Vellume 훅을
한 번 검토·신뢰해야 합니다. 자동 감지는 세션 파일의 내용에 접근하지
않습니다. 상세 Hook을 켜도 사용자 요청, 명령문, 도구 입력·출력,
응답 본문과 대화 기록은 저장하지 않습니다. 프로젝트 구분용 작업 폴더,
상태, 도구 종류, 모델 이름과 갱신 시각만
`%LocalAppData%\Vellume\Codex\status.json`에 저장합니다.

## 데이터 위치

- 설정: `%LocalAppData%\Vellume\settings.json`
- 로그: `%LocalAppData%\Vellume\Logs\vellume.log`
- WebView2 데이터: `%LocalAppData%\Vellume\WebView2`
- 관리형 월페이퍼: `%LocalAppData%\Vellume\Library`
- Codex 브리지와 상태: `%LocalAppData%\Vellume\Codex`
- 복구용 임시 프레임: `%LocalAppData%\Vellume\GpuSafety`

설정 파일은 임시 파일에 쓴 뒤 교체하며 마지막 월페이퍼, 재생 옵션,
위젯 표시 여부와 배치를 복원합니다.
라이브러리의 이미지·GIF·영상·HTML은 항목별 관리 폴더로 복사됩니다.
`settings.json`에는 관리 복사본 경로, 가져온 원본 경로, 종류와 표시 이름을
저장합니다. 가져온 원본은 Vellume이 수정하거나 삭제하지 않습니다.

## 구조

- `Vellume.App`: WPF UI, 단일 인스턴스, 트레이, 설정 편집, 앱 수명 주기
- `Vellume.Core`: 모델, 계약, JSON 설정, 경로·파일 검증, 로그
- `Vellume.Windows`: WorkerW/Win32, 네이티브 이미지·영상·위젯·오버레이와 WebView2 폴백, 모니터,
  프로세스/창 상태와 Codex 브리지
- `Vellume.Renderer.Native`: C++20 x64, WIC, D3D11, Direct2D,
  DirectComposition, Media Foundation 및 바이너리 IPC 렌더 호스트
- `Vellume.Tests`: UI에 의존하지 않는 설정·검증 로직 테스트

월페이퍼와 정보·애드온 위젯은 서로 다른 자식 창입니다.
정보·애드온 레이어는 클릭을 통과시키며 월페이퍼보다 위, Explorer
아이콘보다 아래에 놓입니다. Dock은 하단 중앙의 별도 상호작용 창입니다.

## 알려진 제한사항

- 시계·시스템 정보·Codex 컴패니언·퀵슬롯은 모두 네이티브입니다.
  로컬 HTML 또는 시스템 코덱이 처리하지 못한 WebM을 사용하면
  월페이퍼 폴백용 WebView2 프로세스가 남습니다.
- 영상에서 밝기·대비·채도를 100%가 아닌 값으로 바꾸면 기존 화면 보정
  호환성을 위해 관리형 렌더러로 전환됩니다. `늘이기` 자체는 C++ 경로에서
  지원합니다.
- `완전 정지` 규칙 중에는 동영상 대신 정지 프레임이 Windows 시스템
  배경으로 보입니다. Vellume 설정·트레이·정책 제어부는 유지되지만
  RenderHost, Dock과 상호작용용 WPF 창은 GPU/DWM 충돌 방지를 위해
  해제됩니다. bounded 정보 위젯 HWND는 숨김·정지 상태로 유지되며,
  대상 프로세스를 종료하거나 모든 표시 창을 최소화하면 새 RenderHost와
  Dock을 복원하고 위젯을 즉시 다시 표시합니다.
- GIF는 WIC 네이티브 경로를 사용합니다. WebM은 Media Foundation을 먼저
  사용하고 설치된 시스템 코덱이 지원하지 않을 때 WebView2로 폴백합니다.
- 규칙이 없는 앱의 자동 일시정지는 현재 사용자가 조작하는 전경 창의
  종류와 표시 크기를 기준으로 합니다. 탐색기·Windows 셸·최소화되었거나
  뒤에 있는 앱·작은 일반 창은 렌더링을 멈추지 않습니다. `실행 중` 규칙을
  명시한 프로세스만 백그라운드 상태에서도 해당 동작을 적용합니다.
- 여러 모니터의 월페이퍼는 지원하지만 위젯과 Dock은 의도적으로 기본
  모니터 한 세트만 사용합니다. 서로 다른 DPI 배율을 섞은 구성과 특수
  Explorer/가상 데스크톱 배치는 추가 실기기 검증이 필요합니다.
- Codex 컴패니언은 공식 수명 주기 이벤트만 표시합니다. 실험적인
  app-server나 비공개 세션 DB를 읽지 않으므로 토큰 스트리밍, 내부 추론,
  세부 진행률은 표시하지 않습니다.
- attention 표시는 Windows Shell의 창 flash 신호이며 Windows 알림
  센터의 알림 내용이나 개수를 읽지 않습니다.
- Windows는 임의의 타사 트레이 아이콘을 열거·복제하는 안정적인 공개 API를
  제공하지 않습니다. Vellume Dock은 원래 트레이를 잠시 표시하는 안전한
  우회 동작을 사용합니다.
- 일부 단일 인스턴스 앱은 Dock의 `새로 실행` 요청을 기존 프로세스로
  전달하므로 새 창 생성 여부가 앱 자체 정책에 따라 달라집니다.
- 네이티브 MP4 코덱 지원은 Windows Media Foundation 환경에 따르며,
  WebView2 폴백 MP4·WebM은 설치된 WebView2 Runtime 환경에 따릅니다.
- 숨김 테스트 HWND에서 C++ 이미지·영상의 첫 프레임, 비계층 창 스타일,
  표시 전환, 일시정지·재개와 안전 종료를 자동 검증합니다. 실제 Explorer
  WorkerW Z-order와 Unreal Editor 조합은 GPU 드라이버별 실화면 A/B 검증이
  추가로 필요합니다.
- 단일 HTML 파일 등록은 선택한 문서만 복사합니다. 같은 폴더의 CSS·JS·이미지를
  상대 경로로 사용하는 웹 월페이퍼는 필요한 파일을 `index.html`과 한 폴더에
  모은 뒤 `HTML 폴더 추가`로 등록해야 전체 리소스가 함께 관리됩니다.
- 로컬 HTML은 JavaScript를 실행할 수 있으므로 신뢰하는 콘텐츠만
  Library에 추가해야 합니다.
- 온라인 마켓, 계정, 결제, 클라우드 동기화, 자동 업데이트는 없습니다.
